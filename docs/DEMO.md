# CareBodha hackathon walkthrough

Use only the fictional seeded accounts. Start PostgreSQL, the web app, and the separate worker using the README commands.

1. **Show the experience.** Open the landing page: “Your doctor’s instructions. Clearly understood.” Scroll through Understand → Explain back → Clarify. Run the fictional inline frequency example; point out that the approved plan is the source.
2. **Approve as the clinician.** Sign in with the Clinician demo button. Select **Asha Sharma**, open **Care-plan review**, and select Recovery care plan v2 (draft). Show original source and structured fields. The prepared fixture has reviewed English/Hindi explanations. Click **Approve and publish**. If v2 is already approved, create a new draft, confirm each extraction, generate explanations, confirm English and Hindi for each instruction, then approve. Explain that the previous version stays published during review.
3. **Read as the patient.** Sign out; use Patient demo. Open **My care plan**, switch English/Hindi, expand the original source, and open an instruction detail. Click **Listen** when a suitable browser voice is installed; otherwise use the visible approved Hindi text.
4. **Find and repair the misunderstanding.** Open the medication's **Explain back**. Enter “I will take one tablet once daily after food.” Show the frequency finding: “You said ‘once daily.’ Your approved instruction says ‘twice daily.’” Retry with “I will take one tablet twice daily after food.” The checked details agree. Explain that this is understanding, not adherence or clinical-safety confirmation.
5. **Share with consent, then revoke.** Open **Family assistance**. Invite `family@carebodha.demo`, choose permissions, and copy the single-use link. Sign out and sign in as Family; open that link and accept. Select Asha's shared plan; complete a caregiver attempt. Return to Patient and revoke Priya's grant. Family refresh/access requests now fail. Priya's separate Ravi grant remains unaffected.
6. **Close the loop.** As Patient, ask a question tied to an instruction. As Clinician, select Asha, open **Clarification queue**, respond, and resolve it. As Patient, read the reply and notification. Schedule a reminder a minute ahead; the worker creates one in-app notification. Mark it read and report completion, showing the separate states.
7. **Prove persistence.** Restart the web app and worker while retaining PostgreSQL and private storage. Sign in again; attempts, plan versions, grants, questions, reminders, and read/completion records remain. The acceptance suite's `pnpm verify:restart` provides an API/database check too.

What to say explicitly: fictional data; deterministic demo comparison; clinician approval required; no independent treatment advice; no email/SMS/push claims; no clinical validation or regulatory-compliance claim. Live AI, enabled OCR, deployment storage, and actual microphone/browser-service transcription need separate integration validation.
